# Brand Icons

Identify the authoritative mark, palette, spacing and naming system before making variants. Distinguish a logo, app icon, functional glyph, mascot and decorative product illustration; each has different clarity constraints. Define silhouette, optical size, stroke/fill grammar and permitted material treatment.

Build a master source with intentional small-size variants. Test actual favicons and toolbar sizes rather than only a huge artboard. A glass material may work on a landing hero but destroy a 16px glyph. Use hue, shape and text together for meaning; do not encode state solely through color. Keep light/dark and monochrome behavior explicit.

Derive SVG, PNG/WebP, platform icon sets and optional 3D/rich-media variants from the same accepted identity. Do not overwrite a mark merely to make its files resemble a new automation recipe. A family resemblance must not erase each product's actual subject.

Acceptance includes source reopening, clean SVG structure, named exports, crisp native-size rendering, collision/recognition comparison and real placement in consumers. Add a motion version only after the static identity works. Record source/export relationships so a token update can trigger the right derivative rebuilds without remaking unrelated art.
