# Cross Media Journeys

Reuse existing journey identifiers, manifests, verdicts and consumers. A new creative pipeline should attach asset/source/export metadata to those contracts, not invent a second canonical success registry. Distinguish authoring-app journeys from exported-media tests and actual product-consumption journeys.

For each asset, capture a trace from brief and source revision to produced bytes, export settings, target component and exercised behavior. Checks must correspond to actual observations: file decode, source reopen, browser input, accessibility semantics, frame progression, errors and screenshots. A self-reported model score is critique, not authoritative proof.

Keep immutable capture masters separate from cropped, narrated, annotated or accelerated presentation edits. Each derivative records its parents and transforms. A structural snapshot with unknown format must not be consumed as ARIA or a scored JSON object simply because its filename says so.

Seed negative cases: missing asset, failed screenshot, unexpected crop, wrong duration, silent audio, broken key input and an unreadable small-screen layout. The apparatus must reject them. Incomplete check sets return INCONCLUSIVE or the appropriate blocked state. Integrate actionable failures into the user's existing product/work system; do not stop at a green exporter receipt.
