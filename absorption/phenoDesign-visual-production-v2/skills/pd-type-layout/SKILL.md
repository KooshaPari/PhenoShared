# Type Layout

Read the real content before defining a grid. Establish one dominant hierarchy and a reading order that survives small screens, translated copy and loading/error states. Choose type roles, measures, weights and spacing from the subject; do not invent decorative labels to fill space. Preserve existing accepted tokens unless a concrete inconsistency requires change.

Prototype two composition hypotheses with real headings and body copy. Compare information density, scanning, focal point and relevance. A default bento grid or giant rounded dashboard is not a design decision. Let the most characteristic product object carry emphasis and keep supporting structure disciplined.

Treat font licensing and installation as dependencies, not embedded system files. Record family/style/PostScript names and legal acquisition references. Check fallback metrics, line breaks, missing glyphs, text scaling and multilingual shaping. Bake only approved display lettering where editable source and accessible equivalent text remain available.

Validate desktop and mobile layouts, narrow widths, 200% zoom, keyboard focus, long strings and blank/error content. Automated overflow and contrast checks supplement—not replace—visual judgment. Return screenshots at the actual placement size plus a concise explanation of the rejected alternative.
