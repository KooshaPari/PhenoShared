# Visual Production

Start from the product, audience, placement and required interaction, not from a favorite renderer. Locate accepted phenoDesign tokens and sources. Write a compact production brief: what must communicate, what may move, what remains useful without motion, and which editable source is authoritative. List plausible simpler alternatives and the observation that would make each preferable.

Select separate authoring, interchange, runtime and validation tools. A Photoshop document is not a runtime; a browser screenshot is not editable source; a Remotion video is not an interactive scene. Use the all-forms matrix and the relevant specialist skills. Keep asset-engine or the accepted worker backend behind phenoDesign's coherent entry point; do not erect a second scheduler just to expose another application.

Produce one thin vertical slice before multiplying assets: author → reopen → export → place in the actual consumer → exercise input/fallbacks → inspect captured output. Record unsupported capabilities as blocked, not as exported. An agent must continue through actual ready implementation work rather than returning another tool shopping list.

Return source paths, export hashes, consumer locations, exact tool/session versions, visual critique and unresolved acceptance checks. This skill routes work; it does not certify results.
