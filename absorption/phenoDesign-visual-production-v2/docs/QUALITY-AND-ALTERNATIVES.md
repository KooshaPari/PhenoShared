# Quality without cargo-cult complexity

The user explicitly likes elaborate product presentation. The goal is not to minimize every effect; it is to make complexity earn its visual and explanatory value. A carefully lit rotating shoe with distinct materials and meaningful construction reveals is appropriate. A random spin, copied gradient and card grid are not an equivalent result.

## Evaluate the actual alternative

| Initial choice | Plausible better alternative | Observation that decides |
|---|---|---|
| Full realtime 3D | Pre-rendered controlled sequence | No free viewpoint/input is needed; it delivers equal fidelity at lower runtime cost |
| 3D for every motif | SVG or layered 2.5D | Silhouette/layer movement communicates the same fact without a scene renderer |
| Rive for every control | Native DOM/CSS/SVG | No complex rig/state blending and standard semantics work better |
| Remotion for every video | FFmpeg or an existing editor | Task is straightforward trimming/encoding, not a programmable composition |
| Native Adobe for resize/export | CLI imaging tool | No layered editing or native app capability is required |
| New render engine in phenoDesign | Existing asset-engine adapter | Existing backend can perform the job with correct isolation/receipts |
| Generate a product mesh | Procedural/rebuilt/licensed mesh | Geometric accuracy and repair time beat model-generation novelty |
| More worker parallelism | Fewer better-qualified workers | Contention, modal conflicts or retries reduce completed trustworthy outcomes |
| More skills | Fix missing actual adapter behavior | Agent already chooses the right tool but cannot safely author/capture/inspect |

## Visual rubric

Assess product specificity, composition/hierarchy, silhouette/geometry, type, materials/light, motion purpose, responsive behavior, interactive clarity, accessibility and technical finish independently. For each defect record actual frame/state, observation, impact and proposed change. A score is a review aid, not a release authority. Strong execution may intentionally use popular colors or treatments; do not ban them merely to appear different.

Build one polished representative asset before scaling a family. Review native size, neutral lighting, small screen and fallback state. Character quality needs an authored silhouette, consistent proportions and expression/rig design—not just primitive shapes. Material quality needs a source/target comparison under controlled conditions. Motion quality needs timing and interruption review, not a single still.

Keep screenshots of failed iterations. Do not rewrite intent after the fact to excuse defects, fake metric values or silently replace missing output with stock imagery. The technical canaries in this kit deliberately test mechanics; they are not the aesthetic target for the final product.
