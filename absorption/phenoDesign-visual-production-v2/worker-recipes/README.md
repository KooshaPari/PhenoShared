# Worker recipes and proof boundaries

These sources demonstrate bounded native authoring paths. They are **not executed Adobe/Blender/Rive results** and are not an already installed automation service. Integrate them into the accepted worker owner (currently asset-engine in the inspected phenoDesign docs) or intentionally migrate that ownership once. The phenoDesign overlay does not create a replacement engine/ directory.

- Illustrator: data-to-JSX compiler + native author/save/export canary.
- Photoshop: command-only UXP local-composition prototype with workspace token, serialized jobs, editable PSD and PNG output.
- After Effects: owned empty-project procedural .aep authoring canary; aerender is a subsequent qualified render step.
- Rive: current CLI/agent source, verification/export/runtime recipe.
- Blender: retained complete original kit at reference/frontend-3d-agent-kit/scripts and its source/GLB assets.

Before production, prove installed API compatibility, source cold reopen, independent export inspection, actual consumer behavior, cancellation, permissions and no operator interference. Native authoring API calls in a syntax-valid script can still fail at runtime. BatchPlay descriptors, Illustrator export behaviors and AE version differences require real host tests. Do not convert a documented prototype into a PASS badge.
