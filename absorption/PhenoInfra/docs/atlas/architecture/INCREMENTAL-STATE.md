# Incremental state and macro visibility

## Separate seven states

Working-tree changes, local commits, remotely published commits, integrated revision, verified artifact, released artifact and adopted installation are independent. A PR merge into an intermediate branch is not default-branch delivery. A closed unmerged PR needs a supersession/cancellation disposition. An amended commit changes identity even if the visible count stays flat.

## Snapshot identity

Capture immutable subject/repository IDs and observed refs with timestamp, actor/access context and coverage. A sequential multi-repo observation is not an atomic fleet snapshot. Preserve additions, renames, access losses and new revisions as events. A missing repo/HTTP 404 does not establish deletion. Names and topic changes do not approve lifecycle changes.

## Incremental context packets

A worker receives only its accepted scope, current baseline, relevant product/architecture neighborhood, open dissatisfaction, required contracts, exact source anchors, consumer dependencies and valid evidence. Expand on demand. Record packet source identities and freshness. Large persistent indexes are allowed; repeatedly injecting the entire corpus is not the default.

## Macro views

Current state answers what the product is, what artifact exists, and what is verified. Movement answers what behavior changed and where it landed. Exceptions identify stale evidence, contradictions, missing native results, uncertain operations, local-only work and blocked decisions. Group by capability slice rather than raw commit count or repository count.

A quiet branch can coexist with real work in another accepted source. A busy branch can be mostly churn. Neither inference should be made without the destination and acceptance receipts. Keep rich audit history available, but generate concise current views automatically.
