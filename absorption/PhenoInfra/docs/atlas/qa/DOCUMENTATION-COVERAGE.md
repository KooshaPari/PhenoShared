# Documentation is an assurance surface

Document families are independently evaluated against actual obligations: intent, product, specification, architecture, interfaces, data, UX, operations, examples, research and delivery. File presence and word count are not their denominator. Mandatory artifact classes and critical/public contracts must be complete; broad noncritical topic coverage uses the accepted independent floor.

Read stronger existing systems before proposing a new layout. Raw prompts, device captures, role assignments, native schema sources and generation recipes must remain owned and source-linked. Preserve exact available human text separately from normalized, redacted and synthesized forms. Acquisition coverage lists inaccessible/skipped/failed inputs; it cannot claim all historical intent without a knowable denominator.

Examples advertised as runnable must execute against the stated version. API/reference generation must match actual public exports and feature profiles. Instructions must lead to the actual built/installed executable rather than a library-only test target. Documentation must distinguish implemented, specified, proposed, experimental, unsupported and superseded behavior.

PhenoDocs renders reusable subject-owned content and projections. Subject identity, license, source links, versions and public/private policy are explicit inputs. Check rendered navigation, search, anchors, media, private indexes and target-specific base paths. Fix the tool when its checks are fake; do not work around it by publishing success badges.

A public visual can be authored concept art or actual evidence, not both without a clear label. Private raw captures should not leak via static site bundles, search indexes or screenshots. Reference whole applicable classes in the QA manifest rather than manufacturing one FR for every heading.
