# Outcome roadmap, not calendar promises

## Phase A: bind and expose

Resolve current identity/accepted roles and active work. Use existing audits instead of restarting them. Establish minimal interchange/source-anchor contracts and map each product's actual public artifact. Topic cleanup and SROC/CDP recovery are narrow parallel tasks, not a universal prerequisite to implementation.

## Phase B: meaningful proof and first useful repairs

Qualify native checkers and negative controls. Product pairs define a useful bounded witness, characterize preserved semantics and build a competent comparison baseline. Fix already understood real defects while mechanical inventory continues. Tracera integrates its first persistent product path rather than ten separate graph prototypes.

## Phase C: dependency-backed compression

Replace a selected custom subsystem only after preserved contracts and consumer tests exist. Show concrete maintenance reduction, not LOC theatre. Coordinate pooled foundation changes by actual consumer contracts and target leases. Do not let final repo absorptions displace current usable-product work.

## Phase D: qualify, install and learn

Test the integrated artifact outside the source tree, run the case study/pilot, publish only under actual authority, and record installed identity/adoption. Negative pilot results produce evidence-backed product/reuse decisions. Continue to the next bounded slice while the full accepted horizon remains visible.

There is no fabricated duration. `work/tasks.json` has null estimates until real local scope is established. Session seats, native resources and review capacity are separate constraints.
