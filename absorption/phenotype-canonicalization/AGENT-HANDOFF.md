## Required decision discipline

Before selecting or replacing anything, record the capability, constraints, current provider and consumer, existing accepted default, actual alternatives, acceptance tests and expected outcome. Consider the current implementation improved in place, an external library, a shared-provider extension, a narrow adapter, a separate supported profile, and a new implementation. Choose on evidence rather than familiarity or novelty alone.

The directions are OXC lint/format where qualified, native TypeScript, Bun, uv, Python 3.14t, Lefthook, maintained FastMCP, stronger shared consumption and aggressive language/library/algorithm exploration. These are not instructions to delete every occurrence of ESLint, `tsc`, Node or ordinary Python. In particular, TypeScript 7 RC+ uses `tsc`; identify compiler implementation by resolved package/version/binary, not command spelling.

Unknown or incompatible facts result in scoped evidence gathering, a blocked capability, an owned temporary exception, or a supported tested profile. Never invent a successful fallback. Never retain an exception indefinitely merely to avoid investigation.

## Shared consumption rule

Product-local implementation should focus on domain behavior, composition, product content and acceptance tests. Locate common functionality in suitable upstream/shared providers. Prefer improving an owned upstream capability over making a local copy.

PhenoShared should expose narrow installable/importable packages. Do not make every consumer depend on all of docs, graphics, orchestration, infrastructure and Python. Do not create language-bucket ownership boundaries. Bindings are edges; domains own semantics.

For each changed provider, name real consumers and their supported versions/platforms. Prove exact resolution and useful entry-point behavior from a clean consumer without sibling checkouts, repository cwd, globally installed tools or shadow copies. Templates, copied files, declarations and documentation links do not count as adoption by themselves.

PhenoDocs owns shared production/federation plumbing; products own their meaning. Design owns shared primitives/tokens and qualified extension seams; products can remain distinctive. Cross-consumption can be contracts, assets, implementation, data or seamless feature composition—not only visible app embedding.

## Optimization rule

Use `research/candidates.json` as a researched seed set, not a language whitelist or performance ranking. Evaluate other promising candidates when their mechanism fits a real gap. Keep current-language algorithm/data-layout improvement and optimized external libraries in the comparison.

Before promotion retain: baseline revision, workload/input distribution, target CPU/GPU/OS/driver/runtime, correctness or numerical tolerance, build flags, cold/warm timings, repeated samples, boundary/copy/transfer costs, tail latency, throughput, memory, packaging and maintenance consequences. A novel implementation can be an experiment without becoming a production default. A large kernel speedup does not imply a large request speedup.
