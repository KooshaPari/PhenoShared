# Audit justification: phenodag → Tracera + AgilePlus (spec-008 phased migration)

**Date**: 2026-09-01
**Author**: Forge (13-source polyrepo audit, wave J)
**Reference**: registry row `repo-phenodag`
**Decision**: ABSORB → Tracera `crates/tracera-server/src/queue/` + AgilePlus mirror

## Why absorb?

1. **Phased migration complete**: Spec-008 implemented across 4 PRs:
   - `Tracera#723` (commit `ac7b9d1b`) — spec doc + scaffold
   - `Tracera#725` (commit `7afb8916`) — P1: claim/heartbeat/lifecycle
   - `Tracera#727` (commit `fdc2512b`) — P2: dedup/scanner/init/sqlite_init/export/beads_compat/status
   - `AgilePlus#895` (commit `7f9120d5`) — AgilePlus spec mirror

2. **Canonical home verified on remote**:
   - `Tracera/crates/tracera-server/src/queue/` contains 11 absorbed files
     (claim.rs, heartbeat.rs, lifecycle.rs, dedup.rs, scanner.rs,
     sqlite_init.rs, init.rs, export.rs, beads_compat.rs, status.rs,
     + spec.md)
   - `Tracera/docs/specs/008-phenodag-absorption.md` is the migration spec
   - `AgilePlus/docs/specs/008-phenodag-absorption.md` is the mirror

3. **Source repo is a thin redirector**: per the phenodag source README/CHANGELOG
   self-confirmation (2026-07-05 D3 sponsor decision), the Go source repo
   was explicitly downgraded to a redirector after the migration completed.

4. **Name-collision disentangled**: `phenotype-registry/crates/pheno-dag/` is
   a *different* product (Rust DAG extracted from BytePort). The Go `phenodag`
   on GH is the multi-agent DAG. Recommend renaming the registry's Rust crate
   to `phenotype-dag-core` to break the collision (separate follow-up).

## Why not merge elsewhere

We deliberately did NOT target:
- `KooshaPari/portage` — portage is the Harbor env substrate; not a DAG.
- `KooshaPari/phenotype-registry/crates/pheno-dag` — already a Rust DAG
  extracted from BytePort; semantic mismatch with the Go multi-agent DAG.
