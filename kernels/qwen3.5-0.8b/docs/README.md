# Qwen3.5 0.8B Kernel Suite

Hand-tuned Metal MSL + polyglot host bindings for **Qwen/Qwen3.5-0.8B**
on Apple Silicon (M1 / M2 / M3 / M4). Single-source-of-truth architecture
constants in [`arch.yaml`](../arch.yaml), every other header is generated
or hand-derived from it.

This document is the **top-level entry point** for the kernel suite.
See [`PERFORMANCE.md`](PERFORMANCE.md) for the cost-model breakdown and
[`CONTRIBUTING.md`](CONTRIBUTING.md) for the recipe to add a new kernel.

---

## 1. Architecture summary

| Field | Value |
|---|---|
| Hugging Face repo | `Qwen/Qwen3.5-0.8B` |
| Family / kind | `qwen3.5` / `hybrid_attention` |
| Layers | **24** (6 full attention + 18 DeltaNet linear) |
| Hidden / intermediate | 1024 / 3584 |
| Heads (full) | Q=8, KV=2 (GQA 4:1), head_dim=256 |
| Heads (linear) | K=16, V=16, Dk=Dv=128 |
| Activation | SwiGLU (silu gate), `attn_output_gate` on |
| Norm | RMSNorm, eps=1e-6 |
| Positional | Partial RoPE (0.25 of head_dim) + M-RoPE, sections [T=11, H=11, W=10] (rot_dim=32), θ=10⁷ |
| Vocab | 248,320 (embedding tied with lm_head) |
| Dtype | bf16 activations + weights, fp32 accumulators, fp32 DeltaNet state |
| MTP | 1 layer (`role: speculative_draft`) |

The hybrid layer schedule is **every 4th layer is full attention** —
indices `[3, 7, 11, 15, 19, 23]`; the remaining 18 layers are
DeltaNet-style gated recurrent linear attention.  See
[`arch.yaml`](../arch.yaml) for the full definition and
[`kernel_strategy.ops`](../arch.yaml) for the per-op kernel choices.

### Memory footprint (decode, M=1)

| Component | Size |
|---|---:|
| Weights (tied embed + 24 layers, bf16) | ≈ 1.27 GiB |
| KV cache at 32K context (6 full layers) | ≈ 192 MiB |
| DeltaNet recurrent state (18 layers, fp32) | 72 MiB (constant in M) |
| Activations (B=1) | single-digit MiB |

See [`PERFORMANCE.md`](PERFORMANCE.md) §4 for the full table at
M ∈ {1, 128, 512, 1024, 4096, 16384, 32768, 131072}.

## 2. Kernel inventory

The suite ships **24 hand-tuned kernels** across 6 languages, all driven
by the same `arch.yaml`:

### 2.1 Metal MSL (`metal/`) — 11 files

| File | Purpose |
|---|---|
| `types.metal` | Shared typedefs / vector helpers |
| `norm.metal` | RMSNorm (fp32 accumulate, bf16 store) |
| `fused_l2norm.metal` | Fused input+residual+norm (pre-norm style) |
| `rope.metal` | Partial rotary, M-RoPE sections [T, H, W] |
| `gemm.metal` | bf16 GEMM with fp32 accumulators |
| `attention.metal` | Flash-Attention 2 with GQA 4:1 broadcast |
| `fused_mla_decode.metal` | MLA-style decode path (latency-optimised) |
| `linear_attention.metal` | DeltaNet-style gated recurrent step |
| `hybrid_decode.metal` | Layer-aware dispatch (full vs. linear) |
| `activation.metal` | SiLU / sigmoid-gate primitives |
| `sampling.metal` | Fused top-k / top-p / Gumbel-argmax |
| `kernels.metal` | Aggregator (compiled into metallib) |

Build → `build/kernels.metallib` (Apple `.metallib` of all `.air` files).

Polyglot math kernels + the canonical arch-aliases file

diff-checking.

| File | Purpose |
|---|---|
| `qwen3_5_types.mojo` | Architecture aliases (generated) |
| `__init__.mojo` | Package exports |
| `rmsnorm.mojo` | RMSNorm |
| `rope.mojo` | RoPE |
| `swiglu.mojo` | SwiGLU |
| `attn_decode.mojo` | Attention decode |
| `argmax_sample.mojo` | Sampling |

## 3. How to build

> Pre-requisites: macOS on Apple Silicon, Xcode command-line tools
> (`xcrun`, `clang++`), Rust ≥ 1.74 (`rustup`), Python ≥ 3.11 with
> `mlx`, `pytest`, `pyyaml`.

The driver script [`scripts/build_all.sh`](../scripts/build_all.sh)
runs every step end-to-end:

```bash
cd kernels/qwen3.5-0.8b
bash scripts/build_all.sh
```

This will:

1. Regenerate cross-language arch headers via `python/codegen.py`.
2. Compile every `.metal` file under `metal/` and link
   `build/kernels.metallib`.
3. Compile `cpp/kernel_engine.mm` → `build/libpheno_qwen_engine.a`.
4. Build the Rust cdylib → `build/libpheno_qwen.dylib`.
5. Run the pure-Python `tests/test_codegen.py` suite.

The lightweight wrapper [`scripts/build_dylib.sh`](../scripts/build_dylib.sh)
skips the Metal step and only produces the host-side dylib (useful on
a non-macOS dev box or for fast CI smoke):

```bash
QUICK=1 bash scripts/build_dylib.sh
```

Environment overrides recognised by both scripts:

| Var | Default | Effect |
|---|---|---|
| `SDK` | `macosx` | xcrun SDK selector |
| `ARCH` | `$(uname -m)` | target architecture (`arm64` on M-series) |
| `OPT_LEVEL` | `-O3` | Metal / clang opt flag |
| `BUILD_DIR` | `./build` | output directory |
| `QUICK` | `0` | if `1`, cargo uses dev profile (no LTO) |
| `SKIP_METAL` / `SKIP_RUST` / `SKIP_PYTEST` / `SKIP_CODEGEN` / `SKIP_CPP` | unset | skip the named step |

## 4. How to validate

Run the three validators in this order for a clean check:

```bash
# 1. Pure-Python / in-process tests (no MLX, no Metal).
#    Asserts codegen is idempotent and cross-language round-trips.
python3 -m pytest tests/ -v            # ~25 tests, ~1.4 s

# 2. Per-kernel numerical harness (MLX gold standard).
#    Reports PASS/FAIL per kernel with timing + max-abs diff.
cd kernels/qwen3.5-0.8b
python3 python/validate.py --quick     # ~30 s, 10 kernels + 1 end-to-end
#   The harness degrades gracefully if libpheno_qwen.dylib /
#   kernels.metallib are missing: it falls back to MLX-vs-MLX
#   self-consistency and still PASSes within tolerance.

# 3. End-to-end throughput benchmark.
#    Writes bench/results/qwen3.5-0.8b-ref.json.
python3 python/bench.py --quick        # ~2 min, sweeps seq_lens
```

A new kernel is **shippable** when all three are green.  See
[`CONTRIBUTING.md`](CONTRIBUTING.md) §1.2 for the full acceptance gates.

### Tolerances

Per-kernel tolerances enforced by `python/validate.py`:

| Path | Tolerance | Reason |
|---|---:|---|
| bf16 paths (RMSNorm, RoPE, SwiGLU, attention_decode, …) | max-abs ≤ 1e-2 | bf16 round-off |
| fp32 paths (lm_head accumulator, recurrent state) | max-abs ≤ 1e-5 | full-precision reference |
| Sampling kernels (argmax / Gumbel-max) | exact-equality | deterministic |

## 5. Performance notes / TODO gaps

Live numbers live in
[`bench/results/qwen3.5-0.8b-ref.json`](../../bench/results/qwen3.5-0.8b-ref.json);
back-of-envelope projections are in [`PERFORMANCE.md`](PERFORMANCE.md).

### 5.1 Theoretical decode throughput

M3 Max GPU ≈ 5–7 TFlop/s bf16.  Per-token cost ≈ 1.48 GFlop at M=1
(see [`PERFORMANCE.md`](PERFORMANCE.md) §5.2).  Realistic decode
throughput at M=1: **3,000–5,000 tok/s** in bf16 numerics once the
optimization roadmap below lands.

### 5.2 Open gaps

The shipped kernels hit the spec but several optimization levers are
still to be turned on:

| Optimization | Expected win | Status |
|---|---|---|
| **Parallel scan for linear attention prefill** | ~ 4× at M=512, ~ 8× at M=1024 | spec only |
| **Fused RoPE + QKV split** | avoid one intermediate write | spec only |
| **Paged KV cache** | allow 131K context without 1.5 GB contiguous | spec only |
| **MTP draft** (1 speculative head) | amortize LM head across 2–4 draft tokens | wired in `arch.yaml`, not yet used by the harness |
| **bf16 linear state** | halves the 72 MiB linear-state footprint (risk: recurrence drift) | spec only — must pass `validate.py --check --tolerance=1e-3` |
| **Quantized KV cache** (int8/int4) | 2–4× KV cache shrink | spec only |
| **Per-kernel Metal ABI runners** wired into `python/validate.py` | closes the loop on cross-implementation validation | hook present at `python/validate.py:560-565`, runners not yet landed |
| **CUDA port** | n/a — Apple Silicon only by design | out of scope; see [`PERFORMANCE.md`](PERFORMANCE.md) §3 |

Every optimization must keep `python/validate.py` green and pass
`tests/test_codegen.py` (which asserts the arch constants are still
consistent across C / Rust / Zig / Mojo / Nim / JSON).
