# ADR-004 — Dependencies before bespoke duplication

**Status:** Proposed in this package; not a fabricated accepted human decision.  
**Source:** INT-001 and carried prior constraints.  
**Date:** 2026-09-15.

## Context

Custom infrastructure consumes maintenance and often trails mature components.

## Decision proposal

Prefer suitable standard/dependency/patch/adapter paths and retain custom code for justified value.

## Alternatives considered

Always handroll; wrap every dependency universally.

## Consequences and verification

License/security/update/exit work remains necessary. Bind the decision to an actual subject/owner and verify through the associated requirements, work and native evidence. A document's existence is not a product implementation or governance transition.

## Reconsideration trigger

Reconsider when measured fit, performance or lifecycle cost changes.

## Revision 1.1 clarification

INT-003 and [ADR-013](ADR-013.md) explicitly extend the reuse preference to our own work and to aggregate consumer outcomes. This does not prescribe a new repository topology; accepted capability/consumer evidence determines the correct boundary.
