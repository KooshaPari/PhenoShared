## 1. Context

The original brief asks for an evaluation + profiling program on a fork of `forge-dev`, with a local-model workhorse ranging from ~0.8 B (draft) to ~35 B (ceiling) on a 3090 Ti (24 GB), plus a Mac fallback. Two rounds of picks have been produced, both wrong in material ways:

- **Round 1 (2026-07-03 morning):** named "Qwen 2.5 7B Instruct AWQ" as workhorse and "Qwen 2.5 0.5B GGUF" as drafter. User feedback: *“2.5 is an old model. it is july 2026. qwen 3.6 is latest public release”*.
- **Round 2 (2026-07-03 afternoon):** first live HF scrape, replaced with `Qwen3-8B AWQ`, `Qwen3-1.7B GGUF`, `Qwen2.5-Coder-32B-AWQ`. User feedback: *“you're still pulling obsolete models. can I ask why?”*.

This revision takes a different posture. **No model SKUs are named in this ADR.** The picks live in `state/hf_scrape/2026-07-03/v2_shortlist.md`, are generated by a reproducible pipeline, and are **explicitly gated on user sign-off** before any weight download. This ADR establishes the *bootstrap process and the constraints*; the picks themselves are the v2 shortlist artifact.

## 2. Decision

The bootstrap is a process + a set of constraints, not a fixed set of model SKUs.

### 2.1 Process

1. **Live HF scrape is the source of truth.** `scripts/hf_scrape_2026_07_03.py` runs against the public Hugging Face Hub via `huggingface_hub` (unauthenticated by default, authenticated with `HF_TOKEN` if the user provides one). Output is `state/hf_scrape/<YYYY-MM-DD>/{models,rejects}.jsonl` + `summary.json`.
2. **Capability-first ranking.** A second script (`scripts/curate_shortlist.py` + the `build_v2_shortlist.py` overlay in the scrape dir) sorts by capability signals (downloads as a coarse proxy + owner-only canonical flagship + latest-modified timestamp + family presence in the corpus) — **not** by raw download count alone.
3. **vRAM honesty check.** Every pick is annotated with the vRAM truth: dense N B BF16 needs 2N GB; AWQ-INT4 needs ≈ N/2.4 GB; GGUF Q4_0 needs ≈ N/2 GB. Anything that doesn't fit 24 GB at AWQ-INT4 is flagged honestly with the rejection reason (the v2 shortlist's T3/T4 picks all hit this).
4. **Weekly re-scrape + diff.** `pheno-serve-dev` will run the scrape weekly and produce a new `<YYYY-MM-DD>/` for diffing. Any material change updates this ADR's picks and emits a new ADR revision.
5. **User sign-off gate.** No model is downloaded, served, or routed through `omniroute-dev` until the user signs off on `v2_shortlist.md` (the open questions block at the bottom of that file is the gate).

### 2.2 Constraints (these are the actual hard rules)

- **Hardware ceiling:** 3090 Ti = 24 GB VRAM.
- **Dense model vRAM reality:**
  - 1–3 B dense: BF16 fits; AWQ-INT4 always fits.
  - 4–8 B dense: BF16 borderline (with KV pressure); AWQ-INT4 fits.
  - 12 B dense: BF16 exactly fills 24 GB with no KV headroom → **AWQ-INT4 only** in practice.
  - 24 B dense: BF16 = 48 GB → **does NOT fit**; AWQ-INT4 (~13 GB) fits with KV budget.
  - 27 B dense: AWQ-INT4 (~15 GB) fits tight.
  - 32 B dense: AWQ-INT4 (~18 GB) fits.
  - 35 B dense: AWQ-INT4 (~20 GB) is the absolute ceiling.
- **MoE does NOT save VRAM on a single card.** All weights must be resident. The only thing MoE saves is compute per token. So a 30B-A3B MoE needs ~60 GB at BF16 (or ~16 GB at AWQ-INT4 of total weights) — the AWQ-INT4 fit is feasible; the compute win is real but secondary.
- **Drafter / spec-dec path:** ~1–2 B dense, GGUF Q4_0, ~2 GB vRAM, always-on alongside the main model. Speculative-decode draft headroom is part of the main model's KV budget.
- **Engine choice (unchanged from initial draft):**
  - **Primary:** SGLang 0.5.2 (already in py3.13, supports AWQ + GGUF-draft + EAGLE-2 + chunked prefill + paged-KV; aligns with `config/inference_runners.yaml`).
  - **Secondary:** vLLM 0.20.0 (already in py3.13; cross-check, divergent-cache KV offload, prefix-cache replay).
  - **Tertiary:** llama.cpp / ik_llama (only if SGLang or vLLM cannot serve a chosen model).
  - **Mac fallback:** llama.cpp/MLX (only for the GGUF drafter, on the M1 Pro).
  - **Not used for now:** TensorRT-LLM (compile overhead on 3090 Ti ≈ 30 min per model per calibration; hits `RISKS.md` §4 invalid-comparisons risk).

### 2.3 Cloud baselines (always available, used for upper-bound comparison)

- `inclusionai/Ling-2.6-flash` via OpenRouter (104 B / 7.4 B active MoE, 262 K context, $0.01 / $0.03 per 1M tokens on 2026-07-03, 90% promo). User-confirmed: Ling is the **cloud model**, not the workhorse.
- `MiniMax M3` (the model that wrote these docs) via the same router. Used for the second cloud baseline per the user's instruction.
- v2 shortlist also proposes `deepseek-ai/DeepSeek-V4-Flash-DSpark` as a third candidate — see v2 shortlist open questions.

## 4. Consequences

- **No more "stale-SKU risk" for the local baseline:** the `state/hf_scrape/` directory is the canonical source. The next sweep (planned for 2026-07-11) will diff against this one and update the v2 shortlist if anything material moves.
- **The scrape pipeline is reusable** (`scripts/hf_scrape_2026_07_03.py` + `scripts/curate_shortlist.py`) — `pheno-serve-dev` will run it weekly.
- **The picks are now evidence-backed** — every SKU in the v2 shortlist cites its downloads, last-modified date, license, vRAM requirement, and rationale directly from the live API.
- **Sign-off gate is explicit.** The v2 shortlist has an "Open for your input" block with 4 questions for you. Until those are answered, no weights are downloaded.

## 5. Open

- **Sign-off on `v2_shortlist.md` picks** — see the "Open for your input" block at the bottom of that file (T2 workhorse choice, cloud baseline B, AWQ-only fit acceptance, `HF_TOKEN`).
- **`HF_TOKEN`** so the weekly re-scrape can include gated / private models (Meta-Llama-3.x, Mistral-Codestral, Mistral-Small, Yi-34B, etc.). The 2026-07-03 sweep was unauthenticated; gated models are missing from `models.jsonl`.
- **vLLM-vs-SGLang latency/throughput bakeoff** on the chosen T2 pick is not yet run. The `kv_bakeoff` script (`scripts/kv_bakeoff.py`) is wired and will be the first thing we run after the weights land. See `docs/specs/004-implementation-plan.md` §4 (PR #2).
- **M1 Pro 16 GB profile.** v2 shortlist's GGUF drafter picks are the M1 Pro target. Actual MLX-vs-llama.cpp latency on M1 Pro is TBD.
