# v0.11 Cross-Repo PR-Merge Policy

**Effective:** 2026-08-10
**Scope:** Pheno fleet (Benchora, Grapheon, Eidolon, RepoLedger, ResearchLedger, Melosviz, pheno, HexaKit, AgilePlus, OmniRoute)
**Owner:** forge (agent CLI)
**Refs:** v0.12 WBS-PERT-100 task 52; AGENTS.md §10.4 (push auth).

## 1. Authorization gate

Cross-repo PR merges are gated on explicit user authorization. The gate
fires **per cycle**. A single "merge lane X PRs" or "merge everything"
authorization covers all PRs in that lane for that cycle.

**Carry-over:** if a PR is opened in cycle N and not merged in cycle N,
the authorization MUST be re-confirmed for cycle N+1. There is no
implicit carry-forward.

**Push safety:** `git push` to any of the 10 fleet repos is permitted
only after the merge authorization is in effect. The risky-action gate
(`config/risky_action_gate.yaml`) is unchanged.

## 2. Merge strategy

Default merge strategy: **`--merge` (regular merge commit)**.

Rationale:
- Preserves branch tip history (allows `git log <branch>` to resolve
  post-merge for 60+ days).
- Simplifies cross-repo bisect when a single repo carries a stacked
  cross-repo dependency.
- Avoids rebase pitfalls for shared branches like `chore/add-codeowners-20260808`
  that were authored across multiple repos on the same day.

Alternatives reserved for specific cases:
- `--squash` — only when the PR is a single conceptual change and the
  history is noisy (e.g., the author's branch picked up merge commits
  from prior local rebases).
- `--rebase` — only when the PR is a tidy fast-forward and the author
  explicitly requested it.

## 3. Branch deletion

Default: **`--delete-branch`** flag on `gh pr merge` (auto-delete head
branch on origin).

Rationale:
- Lane-E WBS PRs are atomic per-day; the head branch has no further use.
- Lane-F type-ignore-audit PRs are point-in-time fixes; the head branch
  is single-purpose.

Exceptions:
- Worktrees (`worktrees/f1-behave-stubs`, `worktrees/f2-behave-stubs`)
  → preserve local branch ref. The branch carries the rebased commit
  even after the PR closes.
- Recovery branches (`recovery/melosviz-local-20260726`) → preserve on
  origin regardless of merge state. These are archive-quality.

## 4. CI gates

Before merging, the PR MUST have:
- Green `ci` workflow run on the most recent commit.
- Green `merge-queue` (if repo uses Mergify).
- 0 unresolved review comments.

If any of the above are red, the PR is **blocked: <reason>** in the
audit, not force-merged.

## 5. Conflict resolution

If a PR has a merge conflict OR fails CI:
1. Tag the PR in the audit with `blocked: <reason>`.
2. Notify the user (inter-agent message).
3. Do **not** force-merge. Do **not** reset/rebase on the user's behalf
   without authorization.
4. The PR remains open across cycles until the user reauthorizes
   reconciliation.

## 6. Audit trail

Every merge action is recorded in:
- `docs/cross-repo/post-merge-2026-08-10.md` (per cycle).
- `docs/plans/2026-08-10-v0.11-cross-repo-merge-audit.md` (cycle summary).

Both are committed to `pheno-harness:main` and pushed to origin.

## 7. Out of scope

This policy does **not** govern:
- Merges to `phenoforge/airlock` (separate authorization per repo).
- Releases / tag-move RFCs (handled per `docs/plans/2026-08-10-v0.11-tag-move-rfc.md`).
- WIP daemon auto-commits (governed by `AGENTS.md §10.5`).
