### Phase 1 — Reconciliation preflight test fix-up (6-25)
- 14 reconciliation test failures → 0 failures (was the post-v0.8 audit's
  "out-of-scope" bucket). Net delta: 22 passed → 36 passed, 0 failed.
- Root-cause: production code looked up `_run_git`, `_read_packet_file`,
  `_PACKET_FILE_MAX_BYTES`, `_PACKET_TOTAL_MAX_BYTES`,
  `_REMOTE_SNAPSHOT_MAX_BYTES` via local module globals, which doesn't
  apply when tests `patch.object` the public re-export module
  (`scripts.reconciliation_preflight`). Fixed by routing all call sites
  through the public module's namespace.
- `_verify_bundle` no longer uses stdin (`bundle verify -`); writes to a
  tempfile and verifies via path. Git's stdin verification uses
  rev-list internally and fails spuriously with "prerequisite commits
  exist in the object store but are not connected to history" when the
  repo has any unreachable objects — even though those objects aren't
  required by the bundle.
- Closing merge: `15cd83b`

### Phase 2 — evidence_registry `discover()` refactor (26-35)
- 2 evidence_registry test failures → 0 failures (24 passed → 26 passed).
- Same monkey-patching pattern: `MetadataClient`, `HuggingFaceAdapter`,
  `ArxivAdapter`, `persist_page` are now looked up via the public
  `scripts.evidence_registry` namespace at call sites.
- New public API in `pheno/evidence/store.py`:
  - `discover()` returns the parent-module adapter lookup table keyed
    by source kind (arxiv, github, hf, local_corpus, modelscope,
    reddit).
  - `discover_all()` returns the full enumeration (kept separate so

- Both exported via `__all__`.
- New tests at `tests/test_evidence_registry_discover.py` (5 tests).
- Closing commit: `c760e7c`

### Phase 3 — Harbor integration + promotion (36-50)
- 3 harbor-required test failures → 0 failures (15 passed → 18 passed).
- Root cause: `scripts/harbor_consumer_dry_run.py` was failing because
  when invoked directly (`python3 scripts/...`), `sys.path[0]` is the
  `scripts/` directory, not the repo root. The repo's local `harbor/`
  directory is a PEP 420 namespace package (no `__init__.py`, contains
  only `*.ps1` scripts), so `import harbor` fails without the repo
  root on `sys.path`.
- Bootstrap fix: at script load, insert the script's parent's parent
  (the repo root) into `sys.path[0]`.
- Also tightened the test probe `_harbor_installed` to mirror the
  script's runtime check exactly: `importlib.metadata.version('harbor')`
  **plus** `import harbor`. The probe previously only checked version,
  which succeeded even when the package code was missing.
- Closing commit: `39100c8`
