## Summary

Created `scripts/forge_status.sh` — a unified status reporter for the
3 `com.phenoforge.forge-*` LaunchAgents. Outputs are designed for both
human readers (table mode) and automation (JSON mode).

## What it reports (per agent)

| Field | Source | Example |
|-------|--------|---------|
| `label` | literal | `com.phenoforge.forge-watchdog` |
| `pid` | `launchctl list <label>` | `54695` or `(on demand)` |
| `last_exit` | `launchctl list <label>` | `1` or `(on demand)` |
| `next_run` | `launchctl print ... \| awk '/next run/'` | ISO timestamp or `(on demand)` |
| `last_log` | `tail -1 ~/.pheno-harness/logs/<label>.log` | recent log line |

## Modes

```sh
# Human-readable table
bash scripts/forge_status.sh
# AGENT                              PID     EXIT    NEXT-RUN                          LAST-LOG
# ----------------------------------- ------- ------- --------------------------------- --------
# com.phenoforge.forge-watchdog      (on demand) ... [2026-08-11T23:22:19Z] watchdog: degraded (disk=100%, mem=99%, procs=616)
# com.phenoforge.forge-net-heal      (on demand) ... [2026-08-12T01:23:33Z] net-heal: all endpoints reachable
# com.phenoforge.forge-proc-reap     (on demand) ... [2026-08-12T01:23:21Z] proc-reap: nothing to reap

# JSON for scripts
bash scripts/forge_status.sh --json

# Exit code only (0=loaded, 2=partial, 3=unloadable)
bash scripts/forge_status.sh --quiet
```

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | All 3 agents loaded + schedulable |
| 1 | Usage error (unknown arg) |
| 2 | One or more agents not loaded |
| 3 | `launchctl` unavailable (e.g. non-mac host) |

## Implementation notes

- Handles the launchctl quirk where OnDemand agents return a YAML
  block (starting with `{`) instead of the usual `PID EXIT_LABEL`
  format. When the first line begins with `{`, the script tags the
  fields as `(on demand)`.
- Truncates next-run text to 32 chars to keep the table compact.
- Uses `set -euo pipefail` to fail loudly on any unexpected error.
