# v0.10 Launchd Agent Audit (WBS task 96)

**Date:** 2026-08-08
**Status:** PARTIAL — 3 agents enabled, plists broken, force-fire blocked

## TL;DR

The 3 phenoforge launchd agents (`forge-watchdog`, `forge-net-heal`,
`forge-proc-reap`) are **declared enabled** in `launchctl print` but
their `.plist` files in `~/Library/LaunchAgents/` are **incomplete** —
they contain only a `ProgramArguments` array and are missing the
required `Label`, `RunAtLoad`, and `KeepAlive` keys. `launchctl
bootstrap` fails with `Input/output error` and `launchctl kickstart
-k` reports `Could not find service ... in domain for uid`.

The agent **definitions** are loaded (because the plist filename
provides a fallback Label), but they cannot **start** a process.

All 5 plist files have `size: 62-78 bytes` — too small to be valid
launchd property lists (a minimal valid plist is ~250 bytes including
the XML wrapper).

## Plist content sample

```
$ cat ~/Library/LaunchAgents/com.phenoforge.forge-watchdog.plist
["\/bin\/zsh","-c","\/Users\/<REDACTED>\/.forge\/bin\/forge-watchdog.sh once"]
```

This is a bare JSON-encoded `ProgramArguments` value, not an XML
plist. launchd reports the service as `enabled` (because the filename
provides a label) but cannot instantiate the process.

## Root cause

The plist files appear to have been **written as raw JSON values
without an XML plist wrapper**. launchd expects XML like:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.phenoforge.forge-watchdog</string>
    <key>ProgramArguments</key>
    <array>
        <string>/bin/zsh</string>
        <string>-c</string>
        <string>/Users/<REDACTED>/.forge/bin/forge-watchdog.sh once</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <dict>
        <key>SuccessfulExit</key>
        <false/>
        <key>AfterInitialDemand</key>
        <true/>
    </dict>
</dict>
</plist>
```

## Action items

1. **Rewrite each plist** as a proper XML plist (WBS task 96 follow-up).
2. **Add Label** explicitly so renaming the file doesn't break the link.
3. **Add KeepAlive** policy appropriate for each agent's role.
4. **Verify** with `launchctl bootstrap gui/$(id -u) <plist>`.
5. **Force-fire** with `launchctl kickstart -k gui/$(id -u)/<Label>`.

## What still works

- The cron-driven agents (`com.phenotype.*` and `com.phenoforge.forge-*`
  family) are unaffected — they fire on their own schedule and don't
  need launchd KeepAlive.
- The `airlock-v2-cleanup` and `airlock-v2-autocommit` agents are
  present in `~/Library/LaunchAgents/` but disabled; they would need
  the same fix before bootstrap.
