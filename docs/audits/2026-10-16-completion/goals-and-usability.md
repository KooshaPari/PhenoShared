## What counts as unfinished

Observed production placeholders are concrete behavior, not a keyword score: HexaKit emits successful empty crypto, Eye tracker synthesizes landmarks, router Bifrost uses an ID prefix. Unsupported profiles that return errors (Eidolon, PhenoCompose) are different: correctness depends on advertising them accurately. Deliberate fake engines, test adapters, fixtures and template interpolation are legitimate test/tool surfaces. AgilePlus's explicit stub backend does not erase its default real Substrate adapter. No package is sunset merely because it has a TODO.

## Desktop ownership and repository relationships

Phinbox native forms are SwiftUI/AppKit; main/tray/daemon are Rust. `gui/desktop/macos` is a separate MLX Swift package, not Phinbox. No tracked Avalonia `.axaml` or desktop `.sln` was found at this revision; observed `.csproj` files are Unity/tests. Untracked ShareCLI desktop material in the original checkout is preserved and outside this main snapshot. A .NET/Avalonia shell may exist in PhenoApps or another repo, but that is an external-owner question and was not inspected here. Keep Swift and web consumers of the same decision contract until an explicit ownership decision says otherwise.

## What can be used now

Source-level reusable surfaces exist for Substrate planning, TeamComm RPC, Tasken storage/recipes, Settly config, Stashly cache and supported PhenoCompose operations. This audit did not execute or install them, so **usable-now on the operator's machine is UNKNOWN for every row**, not assumed yes from an entrypoint. Phinbox native path, observed HexaKit crypto, synthetic eye tracking, Focus connector CLI and the empty AgilePlus dashboard require completion before the corresponding advertised user outcome can be accepted. A failure in one route does not prove all routes in the family unusable.
