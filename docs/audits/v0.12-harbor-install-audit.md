### Namespace package: is it correct?

The Python docs describe a namespace package as one that is split
across multiple directories, with no `__init__.py`. PEP 420 governs.

For `harbor_cli`:

1. The `pheno-harness/harbor_cli/` directory contains PowerShell scripts
   but no `__init__.py`.
2. No pip-installed `harbor_cli` package exists in this environment
   (`pip list | grep harbor` returns nothing).
3. So `import harbor_cli` returns a namespace package whose `__path__`
   lists only `pheno-harness/harbor_cli/`.

This is correct behavior for the design intent (harbor_cli is a
PowerShell-based terminal-bench runner; the Python side is just a
subprocess caller).

### Risk: a future pip install of `harbor_cli` could shadow

If someone `pip install harbor_cli` later (a hypothetical package of
the same name), the import resolution depends on `sys.path` ordering.
For this reason, the install script `scripts/install_harbor.sh`
(task 90) should:

1. Reject the install if a non-namespace `harbor_cli` is already
   importable from PyPI.
2. Document this risk in `docs/guides/harbor-install.md` (task 92).
