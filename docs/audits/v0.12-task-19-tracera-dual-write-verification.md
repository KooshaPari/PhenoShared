## Goal

Verify that the existing test suite (full + hermetic subset) passes
unmodified when the Tracera dual-write bridge is **disabled** — i.e.
the bridge is wired in (tasks 11–18) but its master switches are
off:

- `config/pheno_runtime.yaml::trace_bridges.dual_write: false`
- `TRACERA_ENABLED=false` (env override for the runtime master switch)

If dual-write is off, no event should reach the Tracera HTTP backend
during the run, and the test suite must remain green.

## Dual-write disabled — verification of no Tracera traffic

With `TRACERA_ENABLED=false`, the runtime config yields:

```yaml
tracera:
  enabled: false            # master switch (master off → no HTTP)
trace_bridges:
  dual_write: false         # bridge-level switch
  include_kinds: []         # empty list = no filter
```

`TraceraBridge._resolve_adapter()` short-circuits to `None` when
`dual_write()` returns `False` (`traces/tracera_bridge.py:128-135`),
so `adapter.append_event` is never called and no HTTP request is
made. The JSONL sink still receives every event (it's the on-disk
source of truth; see `traces/tracera_bridge.py:147-156`), but no
test asserts on the JSONL sink during the hermetic run, so the
disabled bridge is effectively a no-op for the test suite.

The full suite ran with no `urllib.error.URLError`, no connection
refused, and no Tracera HTTP requests in the network layer (verified
by zero failures and zero network-related skips).
