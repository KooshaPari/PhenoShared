## Audit method

```sh
grep -rn "pytest\.skip(\|pytest\.mark\.skipif\|pytest\.importorskip" tests/*.py
```

## Findings

| Pattern | Count | Nature |
|---------|-------|--------|
| `pytest.mark.skipif` | 39 | Build-time known conditions (binary on PATH, dep installed, etc.) |
| `pytest.importorskip` | 2 | Optional dependency not installed (cryptography, huggingface_hub) |
| `pytest.skip(...)` (inline) | 19 | Runtime discovery of missing artifact / config / cron output |

## Pattern classification

### Pattern A — `pytest.mark.skipif` (39 occurrences)

These are applied as decorators/pytestmarks at module level. Best for
conditions known at test-collection time (binary on PATH, dep
installed, Python version).

Example: `@pytest.mark.skipif(not shutil.which("docker"), reason="...")`

**Verdict:** correct usage. No changes needed.

### Pattern B — `pytest.importorskip` (2 occurrences)

Used at module import time for optional deps. Both legitimate:
- `tests/test_artifact_probe.py`: `huggingface_hub`
- `tests/test_signed_benchmark_replay.py`: `cryptography`

**Verdict:** correct usage. No changes needed.

## Refactor opportunity

**2 of 19** inline `pytest.skip()` calls could be promoted to
`pytest.mark.skipif`:

1. `test_evidence_label.py:61` — depends on DAG-24 status (known)
2. `test_metal_simdgroup_constant.py:82` — depends on DAG-41 status (known)

Both depend on the presence of a feature in `bench/contracts/` or
`arch.json`, both of which are deterministic at test-collection time.

## Recommended action

Add a helper module `tests/_harness.py::skipif_no_dag24` and
`skipif_no_dag41` that probe the relevant file. Apply the markers to
the two tests. This is a small, surgical refactor that improves
collection-time feedback (skipped tests show up as `s` not as
`xfail`-like surprises).

**Acceptance:** ac_v1 (commit on main with DAG id footer).

## Conclusion

**PASS.** 19/19 `pytest.skip()` calls are legitimate runtime skips.
2/19 could be promoted to `pytest.mark.skipif` for better collection-
time visibility, but this is a follow-up optimization, not a bug.

The current skip/skipif distribution reflects sound practice:
- 39 skipif markers handle build-time conditions
- 19 inline skips handle runtime discovery (cron outputs, missing
  artifacts, empty modules, host-side state)
- 2 importorskip handle optional Python deps

No structural changes required for v0.12 task 81.
