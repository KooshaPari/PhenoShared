## Pre-existing implementation (already on `main`)

`traces/ingest.py` already implements task 20 (the work landed in an
earlier session, with the v0.12 WBS identifier in the docstring at
line 3). The implementation:

- `TRACERA_DUAL_WRITE_ENV = "TRACERA_DUAL_WRITE"` (line 41) — env var
  used to opt in from the shell.
- `_dual_write_enabled()` (line 372) — returns True when EITHER the env
  var is truthy OR `runtime_config.trace_bridges.dual_write=True`.
- `_build_dual_write_bridge(jsonl_path)` (line 419) — constructs a
  `TraceraBridge` when enabled and the Tracera endpoint is reachable;
  returns `None` (with logged warning) when either check fails. Never
  raises — fail-soft.
- `_to_bridge_event(ev)` (line 489) — converts a `traces.ingest.TraceEvent`
  to a `pheno.trace_store.TraceEvent` matching the field mapping in
  `docs/integrations/tracera-events.md`.
- `collect_all()` (line 311) — branches on whether the bridge is None:
  - bridge present → routes every event through `bridge.emit(...)` so
    both JSONL and Tracera receive the event.
  - bridge absent → falls back to the legacy plain-JSONL write path.

## Operational notes

- **Disabled by default.** Even with `TRACERA_DUAL_WRITE=1` set, the
  feature remains gated by `_has_tracera_endpoint(cfg)` — if the
  TraceraConfig has an empty/unset host, the bridge construction logs a
  warning and the path falls back to JSONL-only.
- **Fail-soft.** Every `try/except` in the bridge construction path
  swallows exceptions (with logging) and returns None, so the production
  ingest never crashes because of a Tracera misconfiguration.
- **JSONL is the source of truth.** The legacy write path is preserved
  unchanged — turning dual-write on never disables the JSONL output.
