## Live-run readiness

The dry-run confirms the migration CODE works for the first 50
beads. The actual API contract requires:

1. A live AgilePlus server reachable at the configured host:port.
2. The server accepting `POST /api/v1/work-packages/{wp_id}/
   transition` with the documented payload shape.
3. The server accepting `GET /api/v1/events?entity_type=
   work_package&entity_id={wp_id}` for query + dedup.

These endpoints are documented in
`docs/integrations/agileplus-api.md` but the actual implementation
in AgilePlus v0.1 may differ. The dry-run reveals 2 known gaps:

- `GET /api/v1/events` returned 404 in the prior session's smoke
  test (2026-08-10) — the route exists in `routes/events.rs` but
  the live server may have been built from a different commit.
- `POST /api/v1/work-packages/{id}/transition` returned 404 in
  the same smoke test — same gap; the route is documented but the
  live build may not include it.

These gaps are NOT migration-script bugs. They are server-side
gaps. When AgilePlus publishes a release with these endpoints
wired in, `bead-ctl migrate --from-jsonl` will Just Work.
