## Pattern analysis

The current convention is **per-file fixtures** — each test file that
needs setup defines its own `@pytest.fixture` (or `@pytest.fixture(scope=...)`)
inline. There is no project-wide `conftest.py`.

This has worked well because:

1. **No fixture pollution.** Each fixture is scoped to its test file.
2. **No shared mutable state.** Tests that need tmp dirs use the
   `tmp_path` fixture, which pytest scopes to the test function.
3. **No conftest discovery surprises.** Pytest discovers `conftest.py`
   files automatically, so an absent conftest at `tests/` is a feature,
   not a bug — it guarantees no global state leaks in.

## Risks of adding `tests/conftest.py`

If we add a `tests/conftest.py` with shared fixtures, the risks are:

1. **Auto-discovery.** Every test would inherit the fixtures, even
   tests that don't ask for them. This is a leak vector.
2. **Module-level state.** A `conftest.py` typically defines
   `pytest_configure`, `pytest_collection_modifyitems`, `autouse=True`
   fixtures, etc. These run for every test, slowing the suite.
3. **Hidden behavior.** New contributors may not realize a conftest
   is influencing their tests (e.g., env-var reset, fixture ordering).

## Recommendation

**Do NOT add a `tests/conftest.py`.** Keep the per-file convention.

If a shared fixture is genuinely needed across multiple test files, the
right place is `tests/_harness.py` (already created in v0.12 task 78-80)
or a similar top-level helper module. The `tests/_harness.py` is
imported by name, not auto-discovered, so its presence is explicit.

## Optional: per-suite conftest

If a sub-package under `tests/` ever needs a shared fixture (e.g.,
`tests/bench/conftest.py` for bench-specific helpers), it can be added
with a narrow scope. There is no such need today.

## Conftest isolation test (task 87)

A test that proves no fixture pollution across test files is meaningful
*as a regression guard*. Suggest:

```python
# tests/test_no_conftest_pollution.py
def test_no_root_conftest():
    """No tests/conftest.py — guard against accidental future additions."""
    assert not Path("tests/conftest.py").exists()
```

This is a one-line sentinel test that fails loudly if someone later
adds `tests/conftest.py` without updating this audit doc.
