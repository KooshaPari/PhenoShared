# IDENTITY-CLAIMS — does PhenoShared describe itself correctly?

**Audit date:** 2026-09-19
**Audited revision:** `a0147e56` (`main`, working tree clean, 29,057 tracked files)
**Remote:** `https://github.com/KooshaPari/PhenoShared.git`
**Scope:** README.md, `crates/README.md`, root `*.md` (128 files), `docs/*.md` (82 files),
`.github/` metadata and all 84 workflow files, and any `*README*` at any level.
**Method:** every number was re-counted from the tree (`git ls-files`, `ls`, `find`,
`cargo metadata --no-deps`); no prose claim was accepted at face value.
**This file is the only artifact created. Nothing else was modified or committed.**

---

## Verdict

**The owner's suspicion is not confirmed, but a bigger problem is.**

The repo's primary identity document is correct. `README.md:1` reads `# PhenoShared`, and
`README.md:3-10` describes it as a container workspace, explicitly names
`KooshaPari/PhenoShared` as canonical, and explains that local clones are often still checked
out as `repos/pheno` and that `KooshaPari/pheno` redirects here. **No document in the repo
presents the container as PhenoAI.** PhenoAI appears only as (i) an absorbed input
(commit `208b0523`, 2026-09-15, +3,870 files), (ii) a one-line origin attribution in the
crate-prefix table (`README.md:200`), and (iii) a stale sibling entry in
`ECOSYSTEM_MAP.md:57`.

The actual defects are:

1. **39 shallow documents title themselves after a *different* project.** The
   clearest are `crates/README.md:1` (`# FocalPoint Crates`), `llms.txt:1` (`# substrate` —
   linked from the README's own documentation map), and `.github/CODEOWNERS:1`
   (`phenotype-infra (canonical)`).
2. **The "reusable workflows" claim is overstated 28×.** `README.md:25,39,249` describe all
   84 workflow files as reusable and "called from other repos". Only **3 of 84** declare
   `on: workflow_call`, which is the only mechanism that permits cross-repo reuse.
3. **The crate-prefix table is internally inconsistent and wrong.** `README.md:200` counts
   `pheno-*` as 117, which is a loose `grep` that also swallows the entire `phenotype-*`
   family it counts again on the next line. `README.md:214` says "others ~60"; the real
   figure is 99 (or 112 on the table's own stated directory basis).
4. **The README's debt section is right about 13 of its 14 items and false about one.**
   `README.md:383-384` says `[workspace.package] repository` still points at a stale URL.
   It points at `https://github.com/KooshaPari/PhenoShared` (`Cargo.toml:89`), fixed by
   `c23adf09` on the same day the README was rewritten.
5. **3,402 tracked files (40,471 occurrences) contain the literal string `<REDACTED>`** where
   the org name or a path belongs, including the title of the ecosystem map
   (`ECOSYSTEM_MAP.md:1` = `# <REDACTED> Ecosystem Map`). Identity is not just misstated in
   this repo; in places it has been erased.

## 3. Provenance framing: is `pheno-*` = 117 an origin claim?

`README.md:200`:

```
| `pheno-*` | 117 | PhenoAI, PhenoAgent, and shared fleet primitives |
```

The column is headed **Origin**, so this *is* an origin claim, not merely a family label. It
is wrong on both axes.

**Axis 1 — the count is a prefix-matching bug.**
- Claimed: 117.
- First-level dirs matching `pheno-*`: **40** (38 with a manifest).
- The claimed 117 is exactly `ls crates | grep -c '^pheno'` = **117**, which is an unanchored
  prefix match that also captures all 75 `phenotype-*` dirs plus `phenoctl` and
  `phenovcs-observability`.
- Consequence: the table counts the 75 `phenotype-*` crates **twice** — once inside the 117
  (`README.md:200`) and once as their own row (`README.md:201`).
- `README.md:200` and `README.md:201` therefore claim 192 crates where 115 directories exist.

**Axis 2 — the origin attribution is wrong for a large share of the family.**
The `pheno-*` family is not "PhenoAI". Enumerating the 40 first-level `pheno-*` dirs, the
dominant contributor is **PhenoCompose** (16 dirs: `pheno-compose-*`, including
`pheno-compose-phenocompose-cli` and the six `pheno-compose-port-*` crates), followed by

## Appendix B — method notes and limits

- Counts were taken from the working tree at `a0147e56` (clean; `git status --porcelain`
  empty). Numbers marked "stale" rather than "false" were re-derived at the README's own
  commit `43e1df50` to separate drift from error.
- `cargo metadata --no-deps` was run against the repo; it resolves workspace members
  authoritatively, including path dependencies that are auto-promoted to members. This is why
  the README's `[workspace].members`-based derivation and cargo's count disagree.
- The 207 non-`PhenoShared` H1 count is mechanical and includes neutral titles. The 39
  enumerated in §1b are the ones that name a *different project as the subject of this repo*;
  the boundary between §1b and §1c is a judgement call in three cases
  (`phenotype-shared`, `phenotype-shared-temp`, `phenotype-infra`) and the evidence for each
  classification is cited inline.
- Claims about the Phenotype fleet as a whole (consumer repos, cross-repo workflow usage,
  `ECOSYSTEM_MAP.md` roster) are marked as fleet claims, not judged false against this repo.
- Not checked: whether any external repo actually calls the 3 `workflow_call` workflows, and
