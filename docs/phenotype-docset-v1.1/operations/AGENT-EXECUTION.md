# Agent execution and integration

Ten Tracera seats and two per other product are a session-capacity design. They do not imply equal implementation priority, permission to modify every repository, or unlimited hardware. Pooled foundations/support have their own small owners and resource leases.

## Pair contract

The product owner maps and implements the accepted bounded target. The assurance/comparison owner actively constructs missing tests and independent baselines, challenges assumptions and verifies the actual artifact. Both can write, but not concurrently to the same uncontrolled worktree/paths. A named integration owner accepts the joint change against a fixed base.

## Handoff fields

Actual repository ID/name/root, worktree/branch/head, accepted parent outcome, scope/permissions, relevant source/model neighborhood, current evidence, missing obligations, task dependencies, writes permitted, tests, artifact, rollback, next action and blocker owner. No agent should need to read several giant historical corpora to find its current acceptance target.

## Depth-first progress

Close a useful encapsulated slice through its actual public workflow before starting a large number of unrelated improvements. Do not drop the wider accepted horizon. Local repair completion, PR readiness, integration, product verification, publication and operator adoption remain separate. External blockers release execution capacity only with exact owned next actions and wakeup conditions.

## Concurrency and recovery

Use unique worktrees and path leases, especially manifests, lockfiles, schema migrations, generated indexes and shared workflows. Reconcile uncertain remote outcomes before retrying. A dropped session does not prove a mutation failed. Record idempotency keys/receipts where the action supports them; no generic retry layer may repeat a side effect blindly.

## Resource admission

CPU compilation, memory-heavy indexes, browser/native capture, GPU render/inference, external provider quotas and review capacity have separate semaphores/leases and priorities. Foreground games and live audio receive protected capacity. Do not infer that 54 chats permit 54 concurrent Rust builds. Benchmark instrumented and uninstrumented paths separately.

## Minimal decisive checkpoints

After current-state binding, report the first useful path and largest unknown. After an implementation change, report actual tests and the artifact. After integration, recheck the integrated revision. After installation, record the exact executable identity and actual task. Keep status concise; emit details as linked evidence rather than repeated walls of narrative.

## Continuing responsibility beyond the local repository

Use [ecosystem-first evolution](../architecture/ECOSYSTEM-FIRST-EVOLUTION.md). Capture owned and external reuse opportunities during normal work; keep unaccepted large refactors out of urgent repairs. Consumers and shared capabilities have explicit source, integration and verification owners. Path leases remain exclusive. Partial local completion must preserve linked consumer/adoption tasks and their parent outcome. New consumer or upstream-change evidence can reopen a boundary decision without reopening the whole portfolio.
