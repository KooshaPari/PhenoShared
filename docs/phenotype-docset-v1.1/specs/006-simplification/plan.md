# Implementation and verification plan — Reuse and semantic compression

Start from the real current subject scope and existing artifacts. Identify the smallest useful acceptance path, its source anchors and missing evidence. Review the requirements in spec.md against actual platform and product obligations; preserve explicit uncertainty.

Reuse established tools and contracts where they fit. Compare alternatives at the behavioral boundary rather than their names or headline feature counts. Decompose approved implementation into path-scoped tasks with a sole integration owner, actual write permissions, negative controls and rollback.

Do not advance from authored spec to verified or shipped merely because files exist. Run the meaningful tests against the integrated candidate and preserve source/tool/config/artifact identities. An environment blocker needs a named owner/action and wakeup. The exact actual engine receipt must be obtained from the appropriate repo-scoped service rather than fabricated from metadata.

The associated work packages below are a planning projection of the global DAG. They are not independent duplicate work records; retain the canonical task IDs when importing into actual governance.
