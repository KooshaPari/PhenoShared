# ADR-014: SROC/CDP Terminology Resolution

**Status:** Proposed
**Date:** 2026-09-16
**Deciders:** Koosha (portfolio owner)

## Context

The Phenotype portfolio documentation set (docs-3, v1.1) references SROC and CDP as unresolved terminology labels. These acronyms appear in:
- `intent/TERMINOLOGY-AND-CONFLICTS.md`
- Multiple product dossiers
- Portfolio taxonomy

Their expansions are intentionally not invented by the documentation package. The ambiguity does not block atlas, QA, comparison, or CVP work, but it does block:
- Certain ADR decisions that reference these terms
- Product role assignments where SROC/CDP define boundaries
- Cross-repo dependency mapping where these labels appear

## Decision

Resolve SROC/CDP as follows:

### SROC
**Standing:** Uncertain. Possible expansions:
1. **Shared Runtime Orchestration Canvas** - fits the PhenoFabric/PhenoInfra boundary
2. **System of Record Container** - fits the Tracera persistence model
3. **Service Registry and Orchestration Core** - fits the Agentora capability

**Action:** Defer resolution until Tracera first persistent product path is integrated (Phase B). The resolution will emerge from actual implementation rather than premature naming.

### CDP
**Standing:** Uncertain. Possible expansions:
1. **Capability Delivery Pipeline** - fits the work integration plane
2. **Cross-domain Data Plane** - fits the PhenoInfra role
3. **Continuous Deployment Protocol** - fits the BytePort/Portage role

**Action:** Defer resolution until Phase B witness journey is complete. The actual deployment pattern will determine the correct expansion.

## Consequences

- SROC/CDP remain labels, not decisions, through Phase A
- No product role is blocked by this deferral
- ADR-014 supersedes any future ad-hoc expansion attempts
- Resolution tracked in `work/tasks.json` as a Phase B dependency
