## 4. Comparator and reuse hypotheses

Initial baselines to verify and version-pin:

- Manual Git/search/specification workflow
- Backstage software catalog plus search
- StrictDoc plus source links
- SCIP/LSP search plus a dependency explorer
- CodeScene-style hotspot analysis

These are a pilot shortlist seed, not an exhaustive SOTA dossier. Expand the relevant family search to the agreed breadth using primary sources; classify peers, upstreams, adjacent tools and implementation dependencies separately. Do not compare an owned full application with a competitor's most primitive demo, or force every alternative into an unnatural architecture.

Reuse directions:

- Adopt SCIP/LSP and language-native indexing rather than recreate symbol engines
- Reuse established local text search and databases
- Adapt software catalogs and requirement formats
- Use native test/report formats as evidence producers

Every substantial custom subsystem needs a retain/adopt/patch/wrap decision with actual functional, timing, data, security, portability and maintenance trade-offs. A smaller source diff is not automatically a better architecture.

## 5. Controlled pilot

Import three representative owned products with seeded and retained-real gaps: an unreachable public capability, stale coverage evidence, a changed dependency, a duplicated owner and a legitimate exception. Ask an unfamiliar operator to explain current behavior, locate the issue, identify affected consumers and plan a bounded repair. Repeat after a source change and restart.

Use fixed versioned inputs and independent outcome oracles. Run matched conditions to isolate mechanisms and a separate idiomatic implementation to compare practical products. Retain failed attempts, intervention logs and infrastructure outcomes. Assign confidence intervals or explicit uncertainty; do not infer a universal winner from one run.

Failure and negative-control cases:

- Stale revision is presented as current
- Unsupported dynamic edge is asserted as proven
- Replayed ingestion duplicates entities
- Untrusted repository prose becomes a command
- Private evidence leaks into a public projection
- Conflicting requirement is silently overwritten
