- Parsec plus platform file/clipboard sharing

These are a pilot shortlist seed, not an exhaustive SOTA dossier. Expand the relevant family search to the agreed breadth using primary sources; classify peers, upstreams, adjacent tools and implementation dependencies separately. Do not compare an owned full application with a competitor's most primitive demo, or force every alternative into an unnatural architecture.

Reuse directions:

- Reuse mature local input/media/shared-memory mechanisms
- Adapt established streaming and remoting
- Use explicit device/codec capability negotiation
- Reuse schedulers/object stores at boundaries that fit

Every substantial custom subsystem needs a retain/adopt/patch/wrap decision with actual functional, timing, data, security, portability and maintenance trade-offs. A smaller source diff is not automatically a better architecture.

## 5. Controlled pilot

Desk-to-laptop-to-desk operation with one real application and two actual nodes. Then add a same-host VM route. Keep keyboard/mouse ownership exclusive, switch presentation/audio, transfer one clipboard/file item and recover from a disconnect. Measure each locality cohort separately while background build/inference load runs.

Use fixed versioned inputs and independent outcome oracles. Run matched conditions to isolate mechanisms and a separate idiomatic implementation to compare practical products. Retain failed attempts, intervention logs and infrastructure outcomes. Assign confidence intervals or explicit uncertainty; do not infer a universal winner from one run.

Failure and negative-control cases:

- Stale input lease causes duplicate control
- Audio feedback or unbounded buffering
- Secret clipboard delivered to wrong session
- Unknown capability accepted
- Disconnect loses or repeats an action
- Protected foreground deadline missed
- Codec assumption unsupported by endpoint
