## 5. Controlled pilot

Deploy one stateless and one small stateful application through the actual supported target. Change configuration, publish a bad image, fail readiness, introduce a data migration and roll back according to the declared policy. Use a clean machine without private sibling checkouts.

Use fixed versioned inputs and independent outcome oracles. Run matched conditions to isolate mechanisms and a separate idiomatic implementation to compare practical products. Retain failed attempts, intervention logs and infrastructure outcomes. Assign confidence intervals or explicit uncertainty; do not infer a universal winner from one run.

Failure and negative-control cases:

- Partial provision reported healthy
- Credentials leak to build logs
- Retry duplicates resources
- Bad image leaves service down without recovery
- Database incorrectly rolled back with binary
- Teardown destroys unowned state
