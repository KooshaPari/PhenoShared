# Foundation and absorbed-capability assignment

Treat PhenoInfra, PhenoTooling, PhenoAI, PhenoGfx and any accepted future Pheno workspace as package/capability collections with precise owners. Do not infer that a shared repository needs one release, one domain, one database or one enormous context packet.

Map every actual capability, public package, source owner, consumers and required support profiles. Recover duplicated and stranded implementations using manifests, histories and consumer evidence, not package names alone. Agentora's framework must not be mistaken for similarly named Cmdra CLI utilities.

For each substantial custom subsystem, evaluate reuse, upstream contribution, focused patch and thin adapter alternatives. Preserve behavior, errors, cancellation, compatibility, isolation and measured performance. Do not create another generic `utils` abstraction or tiny repository merely for agent convenience.

Fix broken verifiers before propagating their verdicts. A replacement checker must execute the advertised check and reject known failures. Verify clean consumer resolution without warm caches or accidental sibling repos. Shared-source moves need source-target-consumer parity and explicit authorization outside this packet.

Deliver bounded packages and qualified consumer contracts to product teams. Support inherited current-target defects without monopolizing product progress behind future integrations. Coordinate target manifests/locks/CI through one integration owner.

## Ecosystem-first consumer contract (revision 1.1)

Prefer reuse, modification, adaptation or a narrow wrapper over a new handrolled mechanism, for external AND owned work. Reason across the polyrepo ecosystem even when writes are restricted to this repository. Account for real current consumers, committed planned consumers and plausible future uses separately; prove current contracts and keep speculative extensibility inexpensive. Do not duplicate owned capabilities, force every product into one framework, or preserve an inferior owned solution without justification.

For substantive changes, attach a proportional consumer-impact and reuse decision to the existing task/PR/ADR: alternatives, affected owners/consumers, preserved semantics/resources, aggregate maintenance and migration effects, verification, rollback and outstanding adoption. A local win must not export greater burden or regressions to other repositories. Small local changes need only a supported no-contract-impact attestation. Coordinate out-of-scope changes with the capability/consumer owners; existing write leases and approval boundaries remain unchanged.

Use [the shared evolution policy](../architecture/ECOSYSTEM-FIRST-EVOLUTION.md) and [copy/paste addendum](ECOSYSTEM-FIRST-ADDENDUM.md). Continue actual bounded delivery rather than restarting a portfolio audit.

## Shared operating contract

Use current repository instructions, accepted scope, actual tools and existing stronger artifacts. This package is a proposed work program and does not grant merge/admin/delete/force-push/publication/DNS authority. Preserve dirty/untracked files, concurrent work, refs, source provenance and private evidence. Bind immutable subject IDs, actual source revision and a unique worktree/path lease before edits. A current prefix/topic or old assistant summary is not a scoped human approval.

Proceed through reversible documented assumptions. Genuine permissions, missing credentials, unsafe actions and unresolved product decisions become owned blockers, not invented results. Do not keep asking for clarification when a read or bounded local preflight can answer it. Do not run unknown hooks or historical code with production credentials. Protect foreground CPU/GPU/audio use with actual resource admission.

Reuse valid audits and evidence after freshness checks. Do not restart the portfolio or regenerate every doc to fit a template. Preserve richer prompt scraping, schema, build, evidence and work systems. AgilePlus and PhenoDocs are tools, not hardcoded portfolio registries. Do not claim an engine transition from files. SROC/CDP remain undefined until their exact prior contract is recovered; do not invent expansions.

Independent unit/integration/E2E and other required assurance families retain at least 85% floors in approved profiles, with stronger accepted floors preserved and critical obligations completely satisfied. Unknown/missing/skipped/unsupported measurements are not passes. Never weaken a denominator, mock required behavior or return success to hide failure. Actual product-source coverage is different from this package's reference-validator tests.

Report task, PR, integration, verified artifact, released artifact and installed/adopted state separately. An inherited repository-local defect can be a separate PR while remaining inside the parent's delivery responsibility. When no safe ready work remains, hand off exact blocker IDs, owners, needed actions and wakeup conditions; do not mark the parent complete.
